### vLLM详解

​	**vLLM**是一个高性能的大语言模型推理和服务框架，它的核心目标是**提高LLM推理时的吞吐量**和**内存效率**。

​	其通过**PagedAttention技术**解决了LLM推理中的内存效率问题，显著提升了吞吐量和硬件利用率。它目前已成为**LLM服务部署的主流选择之一**，**特别适合需要高并发、高吞吐的生产环境**

---



### 传统Attention的问题

在传统的KV Cache（键值缓存）管理中，存在严重的**内存碎片**和**重复存储**问题：

- 预分配的内存空间可能用不完
- 不同请求的内存需求差异大
- 内存利用率低

### PagedAttention原理

借鉴操作系统**虚拟内存分页**的思想：

1. **分块管理**：将KV Cache分成固定大小的块（pages）
2. **非连续存储**：允许连续的逻辑块对应非连续的物理内存
3. **按需分配**：只在实际需要时才分配物理块
4. **共享机制**：不同序列可以共享相同的物理块（如beam search）

```python
# 简化示例：传统方式 vs PagedAttention
# 传统：预分配固定大小的连续内存
traditional_cache = allocate_contiguous_memory(max_seq_len * hidden_size)

# PagedAttention：分块管理
logical_blocks = [block1, block2, block3]  # 逻辑上连续
physical_blocks = {
    block1: physical_addr_5,  # 物理上可以分散
    block2: physical_addr_1,
    block3: physical_addr_8
}
```

### 三、主要特性

#### 1. 高性能推理

- **高吞吐量**：比HuggingFace Transformers提升14-24倍
- **低延迟**：优化的批处理策略
- **连续批处理**：动态调整批处理大小

#### 2. 内存优化

- **KV缓存复用**：支持Prefix Caching
- **内存共享**：并行采样时共享KV缓存
- **动态管理**：实时调整内存分配

#### 3. 易用性

- **兼容OpenAI API**：可直接替换API服务
- **多模型支持**：支持主流LLaMA、Mistral、Qwen等模型
- **量化支持**：支持GPTQ、AWQ等量化格式

---



### 四、架构设计

```reStructuredText
请求队列 → 调度器 → 执行引擎 → 输出
         ↓
      Block管理器
         ↓
      KV缓存池
```



#### 主要组件：

1. **Scheduler**：管理请求优先级和批处理策略
2. **BlockAllocator**：负责内存块的分配和回收
3. **Worker**：实际的模型推理执行单元
4. **CacheEngine**：管理KV缓存的读写

### 五、使用示例

### 基本使用

```python
from vllm import LLM, SamplingParams

# 初始化模型
llm = LLM(model="meta-llama/Llama-2-7b-hf")

# 配置采样参数
sampling_params = SamplingParams(
    temperature=0.8,
    top_p=0.95,
    max_tokens=100
)

# 推理
outputs = llm.generate(
    prompts=["Hello, how are you?"],
    sampling_params=sampling_params
)
```



### 服务部署

```bash
# 启动OpenAI兼容的API服务
python -m vllm.entrypoints.openai.api_server \
    --model meta-llama/Llama-2-7b-hf \
    --port 8000
```
